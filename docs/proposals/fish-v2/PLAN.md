# 鱼缸（fish）重做方案 v2 — 让鱼“像鱼”

> 状态：**已确认并实施**（2026-10-18）。最终尺寸：tiny 12×3 / small 20×5 / medium 30×7 /
> large 38×8；鱼数 `clamp(w*h/1100, 5, 12)`；实现见 `src/scenes/fish.rs`，成图见 `docs/fish.png`、`docs/fish.gif`。
> 预览图：`before-120x36.png`、`after-120x36.png`、`after-200x50.png`、
> `before-zoom.png`、`after-zoom.png`（均为离屏 ASCII 渲染，非最终成图）。

## 1. 现在为什么不像鱼

| 现象 | 根因 |
| --- | --- |
| 看起来是箭头 / 小鱼骨 | `draw_fish` 只画 1 行 `<====o>`：尾巴一个 `<`、身体是 `=`、头是 `>`、眼睛 `o` 正落在“箭杆”末端 |
| 大屏上更细长 | 终端字符格约 **1:2（宽:高）**。按你那张截图量：格子约 **11.5 × 25.7 px**（比例 0.45），画面约 **248 × 57** 格。1 行高的鱼被这套格子横向拉长，越看越像线 |
| 现有“大鱼”也不像 | `huge` 只是把同一条线加长到 7–11 格、加一行 `▓`，没有轮廓、没有鳍、没有分叉尾 |
| 背景把鱼吃掉 | 点阵是满屏 `(x+y*3)%6` 高亮点 + 半亮 `.`，密度和亮度都与鱼同级 |

## 2. 借鉴的成熟做法

- 终端水族馆类程序（如 asciiquarium）与经典 Usenet `fish` 艺术，都是 **固定字符网格 sprite**：分叉尾 + 眼睛 + 嘴 + 背鳍，一眼可辨。
- 本项目已有同类实现可直接复用其代码形态：`mario.rs` 的 `const SPRITE: &[&str]` + 颜色图例、`fairy.rs` 的手绘像素 sprite。

结论：**放弃“用几何图元现算一条线”，改成手绘 sprite 网格**（ASCII 默认，Unicode 用实心块变体）。

## 3. 方案

### 3.1 尺寸档（把鱼做大）

| 档位 | 网格 | 约合像素（你的终端） | 用途 |
| --- | --- | --- | --- |
| tiny | 10 × 3 | 115 × 77 | 鱼群 / 远景 |
| small | 16 × 4 | 184 × 103 | 常见小鱼 |
| medium | 22 × 5 | 253 × 129 | 主力 |
| large | 30 × 8 | 345 × 206 | 画面主角，2–4 条 |

对比现状：现在小鱼 2–5 格、大鱼 7–11 格；新方案 **放大 2–3 倍**，并且是 3–8 行高的立体形状。

### 3.2 鱼的画法（草图，实施时会再对着渲染调）

图例：`#` 身体 / `%` 背脊暗部 / `+` 腹部亮部 / `/ \ _ - ~` 鳍与轮廓 /
`o` 眼睛 / `.` 瞳孔 / `>` 嘴 / `, ' ;` 柔边

medium（22×5，朝右）：

```text
  ##,      ,#####,
  '###,,   ##### o ##;,
   ####################>
  ,###''##############;'
  ##'     '#########'
```

large（30×8，朝右）：

```text
   ##,        ,########,
   '###,      ##########;,
    '###,,    ###### o ###;,
     #########################>
    ,###''###################;'
   ###'    '################'
  ##'        '############'
```

- 左边是**分叉尾**（上下两撇 + 中间缺口），右边是**嘴**，眼睛靠近吻部，避免“箭杆+箭头”。
- 朝左时整块 sprite 镜像（`/`↔`\`、`>`↔`<`、`,`↔`.`、`'`↔`` ` ``）。
- 每条鱼沿用现有 6 色板，但把颜色分配到图例角色上：背脊压暗、腹部提亮、鳍半透、眼睛纯白、嘴提亮 → 靠明暗而不是靠字形来“塑形”。

### 3.3 动画

| 动作 | 做法 |
| --- | --- |
| 摆尾 | 每档 sprite 存 3 帧尾（上摆 / 平 / 下摆），按速度每 ~0.12 s 轮换；只改尾部字符，体形不动 |
| 起伏 | 整条鱼 ±1 行正弦上下浮 |
| 转向 | 到边缘或随机换向时播 3 帧：原样 → 收窄（去掉体侧列）→ 镜像；约 0.25 s，避免“瞬间翻面” |
| 速度 | tiny/small 快、large 慢（大鱼 2.5–4 格/秒），形成远近层次 |
| 编队 | tiny 以 4–9 条为一群同向游动 |

### 3.4 场景与背景（可选项，需你点头）

- 背景点阵亮度 ×0.65、去掉部分高亮点，让鱼“浮”出来（当前背景偏噪）。
- 水色渐变稍微提亮，光柱保留，沙底/水草保留。
- 顶部标题、`n/p` 提示不动。

### 3.5 Unicode 版

同一套 sprite，把 `#`→`█`、`%`→`▓`、`,/;`→`▒`、`'`→`░`、鳍线保留 `/ \ -`、眼睛 `O`。默认仍是 ASCII（遵循 `AGENTS.md`），`--unicode` 才切换。

## 4. 代码改动

`src/scenes/fish.rs`：

- 新增 `struct Sprite { rows: &'static [&'static str], legend: ... }` 或直接 `const` 网格 + `fn glyph_color(ch, base) -> Option<Rgb>`。
- `Fish` 增加 `art: &'static [&'static str]`、`tail_frame: u8`、`turn: Option<TurnAnim>`；去掉 `len`/`huge` 的单行画法。
- `draw_fish` → `draw_sprite`：按 sprite 逐格上色，裁剪、镜像、尾帧、浮动。
- `spawn`：按尺寸档加权（tiny 15% / small 35% / medium 35% / large 15%，终端小于 80×24 时不出现 large）。
- 数量：`clamp(w*h/700, 6, 26)` + 一群 tiny。
- 可选背景调参集中到 `draw_water`。

## 5. 测试与验收

单测（`fish.rs`）：

- 三档 sprite 非空、行宽一致、都能镜像（镜像两次等于原样）。
- ASCII 模式下所有输出字符 `< 0x80`（沿用现有 ASCII-only 测试思路）。
- `large` 覆盖格数 > `medium` > `small`。
- 120×36 下鱼数在区间内、左右方向都存在、`canvas.ink()` 合理。

离屏验收：

- `trix fish --snapshot ... --size 120x36 / 248x57`（ASCII 与 `--unicode` 各一份），用 `tools/ansi2png.py` 出图逐张看；
- 更新 `docs/fish.png`、`docs/fish.gif`，README 特效表与字符集表，CHANGELOG `Unreleased`。
- `cargo fmt --all && cargo test && cargo clippy --all-targets && cargo build --release`。

**通过标准**：120×36 与 248×57、ASCII 下，每条鱼都能靠轮廓（分叉尾 + 眼睛 + 嘴）认出是鱼，且至少三档大小同屏。

## 6. 风险

- 字体差异（你的终端格子更瘦）会让 sprite 看起来更“高”；给尺寸档预留上下 1 行浮动，图例尽量用宽扁字形。
- 鱼多了会互相穿插：按高度分泳道 + 同泳道错开生成，必要时跳过重叠位置。
- CPU：每条鱼 ~30×8 格，20 条仅约 5k 格/帧，可忽略。

## 7. 备选

- **Unicode 半块**（`▀▄█`）可画出更平滑的鱼身，但默认必须 ASCII，只能作为 `--unicode` 增强，不能替代主方案。
- 若目标是“写实照片级”，字符终端做不到；字符画的上限就是“轮廓 + 眼睛 + 鳍”的风格化鱼。
